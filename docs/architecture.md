# Архитектура ФинДруг

Актуально для Android MVP 0.11.0. Это описание работающего кода; документы раннего проектирования не являются описанием текущей реализации.

## Три модуля

| Модуль | Назначение | Зависимости проекта |
| --- | --- | --- |
| `app` | Android Compose, экраны, управление сессией, локальное сохранение и звук | `core:domain` |
| `core:domain` | Чистые Kotlin-модели, контент, правила текущей игры, расчёт движений питомца | Нет |
| `backend` | Отдельный Ktor-сервис с собственными моделями, правилами, JDBC и миграциями PostgreSQL | Нет |

Android работает полностью локально. Он **не подключён к backend**: нет Room, сетевого клиента, outbox или синхронизации. Баланс и прогресс текущего MVP определяются локальными правилами. Backend — самостоятельный серверный компонент с собственными тестами; его наличие в репозитории не означает, что приложение вызывает его API.

## Поток данных Android

```text
MainActivity
  └─ FinDrugApp — создание зависимостей и наблюдение за состоянием
      ├─ GameViewModel — намерения пользователя, сессия, подтверждения, ошибки
      │   ├─ ScenarioGame — проверка правил и новый неизменяемый снимок
      │   └─ GameRepository → LocalGameRepository → ScenarioStore → ScenarioCodec
      └─ GameRoot → GameNavigation → ui/screens/*
          ├─ ui/components + ui/theme + ui/art
          ├─ ui/pet/FoxScene
          └─ audio/GameAudioHost → GameAudio
```

1. Экран получает состояние и функции обратного вызова. Он не создаёт хранилище и не записывает баланс.
2. `GameViewModel` проверяет, что другая запись не выполняется, и вызывает правило `ScenarioGame`.
3. `LocalGameRepository` выполняет операции хранилища на `Dispatchers.IO`.
4. Новый снимок публикуется в `StateFlow` только после успешной записи. При ошибке прежний баланс остаётся на экране, появляется сообщение, повторная попытка доступна.
5. Подтверждения покупок, переводов, получения целей и управления профилем представлены типизированными действиями, а не сохранёнными лямбдами интерфейса.

`GameViewModel` переживает пересоздание Activity. `SavedStateHandle` сохраняет маршрут; игра восстанавливается из хранилища. Небольшое состояние конкретного экрана (страница списка, черновик бюджета) хранится через Compose `rememberSaveable`, где это предусмотрено экраном.

## Навигация и интерфейс

`navigation/GameRoute.kt` определяет обычные экраны и задание с аргументами. `GameNavigation.kt` связывает их с методами ViewModel. Представление маршрута строкой используется только при сохранении, а не внутри экранов.

После создания профиля и получения стартового бюджета `GameRoot` показывает общее нижнее меню `GameBottomNavigation` на всех игровых экранах, включая задания и настройки. Меню занимает отдельную область под экраном, поэтому содержимое и кнопки действий не оказываются за ним. Диалоги и блокировка сохранения действуют поверх всей оболочки. На невысоких экранах `Page` и `Panel` уменьшают отступы; области нажатия сохраняют размер.

`ui/screens/` организован по задачам пользователя: `onboarding`, `home`, `pet`, `profile`, `budget`, `tasks`, `shop`, `savings`, `progress`, `settings`.

Общие кнопки, панели, индикаторы и страничная компоновка находятся в `ui/components/`. Цвета и MaterialTheme — в `ui/theme/`; отрисовка исходных Figma-ресурсов и шрифты — в `ui/art/`. Они остаются частью `app`: отдельный Gradle-модуль для одного клиента сейчас не нужен.

`Page` закрепляет заголовок и основные действия. Содержимое получает оставшуюся высоту, длинные списки разбиваются на страницы. При крупном системном шрифте или открытой клавиатуре текстовая область может прокручиваться.

Звуковой движок принадлежит видимому интерфейсу, освобождает Android-ресурсы при уничтожении и останавливается в фоне. ViewModel выдаёт смысловые сигналы звука, не хранит Activity, Context или SoundPool.

## Локальное сохранение

`ScenarioStore` хранит по одному JSON-снимку для обычной игры и демо в SharedPreferences. Формат описан только в `ScenarioCodec`; имя текущего файла `findrug_scenario_v3` сохранено, чтобы рефакторинг не сбрасывал установленную текущую сборку. Текущий номер формата — 2; это не номер версии приложения.

После уточнения владельца проекта о том, что ранних пользовательских версий нет, удалены старые DataStore-хранилища, импорт прежнего профиля, прежняя цель и миграции старого формата. Поддерживается текущий полный снимок. Демо остаётся изолированным; удаление профиля очищает оба текущих снимка.

## Правила игры

- `ScenarioModels.kt` — состояние, бюджет, отчёты и ответы на задания.
- `ScenarioContent.kt` — товары, цели, суммы доходов и доступ к каталогу.
- `TaskCatalog.kt` — данные заданий; `TaskDefinition.kt` — их структура и валидация.
- `TaskEvaluator.kt` — общая проверка ответов по типу взаимодействия.
- `PeriodEconomy.kt` — лимиты заработка, помощи и покупок за период.
- `ScenarioGame.kt` — переходы состояния, начисления, покупки, накопления, итоги.
- `PetMotion.kt` — независимый от Android расчёт анимаций и ограничение звуковых сигналов.

Старые движки заданий, достижений и питомца, не используемые текущей игрой или сервером, удалены. Правила, которые вызывает backend, находятся в `backend/domain`, а его модели — в `backend/model`.

## Проверки и стиль

- `app/src/test/` — поведение ViewModel при сбое записи, повторных нажатиях, восстановлении маршрута и ошибке чтения.
- `app/src/androidTest/` — сохранения, интерфейс, размещение действий и звук.
- `core/domain/src/test/` — правила текущей игры и движения питомца.
- `backend/src/test/` — API и серверные правила.

```sh
./gradlew formatKotlin
./gradlew checkKotlinFormat
./gradlew :app:testDebugUnitTest :core:domain:test :backend:test
./gradlew :app:lintDebug :app:assembleDebug
./gradlew :app:connectedDebugAndroidTest
```

Форматирование закреплено через ktfmt 0.54, Kotlin style (4 пробела); проверка включена в CI. Android-тестам нужен эмулятор или устройство.

Экономика и оценка периода описаны в [правилах 0.10](game-process-v10.md). Отчёты сохраняют сытость и уход на момент завершения; новые необязательные поля не меняют уже заработанные стадии.

Прогноз копилки — чистая функция `SavingsForecast.kt`. Дополнительные вопросы описаны в `ScenarioTask.reflection`, а их локальный этап и выбор сохраняются через `rememberSaveable` в `TaskPage`; финансовое действие остаётся единственным вызовом получения обычной награды.
