# ФинДруг 0.9: ограниченная экономика и каталог заданий

Экономическая часть заменена [правилами 0.10](game-process-v10.md). Ниже сохранено описание версии 0.9 и устройства каталога.

Основание: пункты 2.1 и 2.5.14 ТЗ Департамента финансов города Москвы. Эти правила заменяют неограниченные выплаты версии 0.6. Суммы выбраны командой; ТЗ требует ограниченности ресурсов, но не устанавливает конкретный лимит.

## Экономика периода

- Стартовый доход — 200, далее 220/240/260/280; начиная с пятого периода — 280. Остаток денег и накопления сохраняются.
- Первое прохождение даёт указанную в каталоге награду (20/30), повтор и короткая тренировка — до 10. **Все эти выплаты вместе ограничены 150 монетами за период.** Последняя выплата при необходимости меньше обычной; её точная сумма видна до начала задания и до получения награды.
- Если общий лимит наград исчерпан и на балансе меньше стоимости самой дешёвой обязательной покупки (сейчас 20), короткая тренировка даёт до 10 из отдельного резерва помощи. Размер выплаты не превышает недостающую до 20 сумму. Всего помощи — **до 20 за период**. Помощь доступна только если оставшийся лимит покупок позволяет обязательную покупку.
- Резерв не восстанавливается от траты или перевода монет, выхода из задания, переключения демо, закрытия приложения. После расходования резерва задания доступны без денежной награды; прохождение засчитывается и позволяет завершить период.
- Суммарные покупки «Нужно» + «Хочу» ограничены **200/220/240/260/280 монетами за период**, в соответствии с его базовым доходом. Это отдельный лимит расходов, а не второй кошелёк. Он виден в бюджете и магазине. Даже большой перенесённый баланс не позволяет купить весь каталог стоимостью 375 монет за один период.
- План покупок также не может превышать этот лимит. Фактическое отклонение от индивидуального плана по категориям по-прежнему возможно и объясняется в итогах, пока общий лимит периода не превышен.
- На перевод в копилку лимит покупок не распространяется. Неизрасходованный баланс не изымается; цели и улучшения остаются доступны.
- Следующий период обновляет оба лимита наград и лимит покупок, сохраняет баланс, накопления, коллекцию и учебный прогресс.

Формулы и проверка покупки находятся в `PeriodEconomy.kt`. Начисление, списание и смена периода — в `ScenarioGame.kt`.

## Нулевой баланс без тупика

Главный экран предлагает помощь, когда денег меньше стоимости самой дешёвой нужной покупки. Короткие тренировки сначала используют обычный лимит наград, затем ограниченный резерв. После получения всех выплат кнопка сообщает «Начать без награды», а завершение — «Завершить задание».

На экране помощи доступна кнопка «Подвести итоги», если уже выполнены условия завершения. Если ни одного задания ещё не пройдено, его можно завершить без денег. В обычном ходе игры нулевой баланс после расходов означает, что финансовое действие уже выполнено; следующий период выдаёт новый доход. Отрицательный баланс не допускается.

## Каталог вместо условий в экранах

- `TaskDefinition.kt` — типы данных и проверка корректности контента.
- `TaskCatalog.kt` — заголовки, темы, описания, предметы, цены, условия, варианты ответа, объяснения и короткие версии заданий.
- `TaskEvaluator.kt` — общая проверка четырёх видов взаимодействия: сортировка, бюджет, выбор с последствиями, корзина.
- `TaskExercisePage.kt` — отображение этих взаимодействий по данным. В нём нет ветвления по номеру задания.

Число заданий, темы в разделе взрослого, счётчики прогресса, достижение за весь каталог, рекомендации и проверка сохранённых маршрутов используют каталог. ID задания и предметов не обязаны быть последовательными. Необходимо сохранять прежние ID: по ним записано прохождение пользователя.

### Добавление ситуации

В список `TaskCatalog.tasks` добавляется `ScenarioTask` с новым ID и одним из существующих типов `Exercise`. Для примера:

```kotlin
ScenarioTask(
    id = 17,
    title = "Бюджет поездки",
    topic = "Бюджет",
    description = "Оставь деньги на обед и на цель.",
    reward = 20,
    exercise = Exercise.Budget(
        total = 80,
        minimumNeed = 30,
        minimumSaving = 20,
        prompt = "Есть 80 монет. На обед нужно 30, на цель отложи хотя бы 20.",
        success = "План готов! Свободно {remaining} монет.",
    ),
)
```

Пример не включён в игровой каталог: в этой версии сохранены прежние шесть заданий. Аналогично можно добавлять ситуации других существующих типов, не изменяя проверяющий движок, маршруты или экран. Новая механика взаимодействия, которой нет среди четырёх шаблонов, потребует отдельной реализации.

Каталог — типизированные Kotlin-данные в исходном коде. Обновление поставляется с новой сборкой APK; серверного редактора и загрузки контента из сети нет. Это не требование конкурсного минимума.

Валидация отклоняет повторяющиеся ID, пустые поля, невозможные бюджеты, корзины с недоступной суммой обязательных покупок и выбор без допустимого ответа. Для телефона допускаются 2–6 предметов сортировки, 2–4 товара корзины и 2–3 кнопки выбора. Для изменения этих границ нужно проверить компоновку.

## Сохранения

В текущий формат 2 добавлены `taskEarnings` и `recoveryEarnings` — суммы за текущий период. При чтении снимка установленной версии 0.8.1 без новых полей уже полученные награды вычисляются по истории текущего периода. Деньги и прогресс не сбрасываются, лимит не открывается заново. Поддержка удалённых ранних прототипов не возвращается.

Проверка и сборка описаны в [emulator-audit-v9.md](emulator-audit-v9.md).
